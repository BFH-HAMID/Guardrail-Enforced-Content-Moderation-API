# Evaluation report

Measured on the working tree at the time of writing (46 policies, 146 tests). Two corpora are scored
with the same harness, and both numbers are reported because they mean different things.

| | **tuned corpus** (225 rows) | **held-out adversarial** (33 rows) |
| --- | --- | --- |
| status accuracy | **100.0%** | **72.7%** |
| stage-1 decision accuracy | 100.0% | 81.8% |
| category accuracy | 100.0% | 69.7% |
| block precision / recall / F1 | 100.0 / 100.0 / 100.0 | **100.0** / 55.0 / 71.0 |
| confusion (TP/FP/FN/TN) | 111 / 0 / 0 / 114 | 11 / 0 / 9 / 13 |
| false-block rate | 0.00% | **0.00%** |
| missed-block rate | 0.00% | 45.00% |
| PII masking recall | 100.0% | 100.0% |
| blocked rows leaking input | 0 | 0 |
| fail-closed rows | 0 | 0 |
| latency p50 / p95 / p99 (ms) | 55.7 / 83.2 / 104.6 | 64.2 / 135.1 / — |

**How to read this pair.** The 100% is a *regression* number: the corpus was generated by the same
author as the rules and iterated against until it passed, so it measures "did I break something I
already handled", not "will this generalize". The 72.7% is the *generalization* estimate: 33 rows
written by hand after the rules were frozen, scored once, with no policy edited in response. The two
numbers that are equal in both columns — **100% precision and 0 false blocks** — are the ones the
design promises: this chain is built to miss novel abuse rather than to punish ordinary text.

## Reproduce it

```bash
python scripts/evaluate.py --limit 0 --modes balanced strict lenient --failures --json -o tests/data/eval_latest.json
python scripts/evaluate.py --dataset tests/data/heldout_adversarial.jsonl --limit 0 --modes balanced strict lenient --json -o tests/data/eval_heldout.json
python scripts/evaluate.py --limit 0 --modes balanced --gate 0.99          # what CI asserts
```

Configuration for both runs (the numbers are meaningless without it):

* `GUARD_LLM_PROVIDER=local` — no network model; the LLM judge and rewrite legs are absent, so
  this measures the **rule layer** (heuristics + `policies.yaml` + PII + the 46 policies). With a
  judge configured, Stage 1 recall on paraphrase-only attacks improves; every response carries
  `flags.degraded=true` when it is not, by design.
* `GUARD_STAGE1_USE_CLASSIFIER=false` for the headline numbers above (the report was produced with
  the classifier stack not installed in the sandbox).
* SQLite, single process, dev box, `concurrency=8`, wall time 1.7 s for 225 rows.
* Both JSON artifacts (`tests/data/eval_latest.json`, `tests/data/eval_heldout.json`) are committed
  and are what the Streamlit "corpus + scores" tab renders — the report cannot drift from the data.

38 rows are flagged `adversarial` (encoding, spacing, leet, homoglyph, cross-lingual, framing) and

## What these numbers do not measure

* **Multilingual breadth.** Coverage is English + Bangla. Other languages are untested; the
  Indic-boundary fix (`indic_safe_pattern`) applies to Bengali, Assamese and friends, but the
  *lexicons* do not exist for them.
* **Long-context smuggling** (harm buried 3 000 words into an innocuous document), multi-turn
  laundering across requests, and tool-output injection — the pipeline is per-request by design.
* **Image, audio, and text-in-image.** Nothing here inspects pixels.
* **Adversarial unicode beyond what is in the corpus** (e.g. tag-block poisoning, RLO chains longer
  than the sanitizer's collapse limits, tokenizer-level tricks).
* **Judge/rewrite behaviour with a real provider**: the headline runs had no LLM. The judge improves
  `ho-inj-002`-style semantic cases; it also adds latency and cost, which is why it is opt-in.
* **Human-outcome agreement.** Every label here is one author's judgement about intent. A real
  deployment needs a second annotator and an inter-annotated slice; `category_accuracy` against a
  single labeller is a consistency check, not a validity proof.
* **Refusal-quality.** "Blocked" says the text did not pass. It does not say the user-facing message
  was helpful, in-language, or correctly escalated to a human.

## Tuning history (same harness, same corpus)

`81.3% → 83.6 → 88.4 → 90.7 → 99.1 → 100.0` status accuracy over ~15 iterations, with each step
recorded in `git log`. The first four jumps were single detector bugs (hex-token splitting, decoded
payloads not entering the view, `\b` killing Bangla patterns, a `None` guard that turned 9 rows into
fail-closed); the last three were policy coverage and the frame/exemption work described in
[docs/POLICIES.md](docs/POLICIES.md).

## Follow-ups worth doing, in priority order

1. **Self-harm method questions without a self-directed frame** (`ho-self-002`) — the class with the
   worst downside. Needs a `_LETHAL_DOSE_RE` on `dose|amount + (kill|die|dead|lethal)`, independent
   of the first-person frame, with a medical-context exception.
2. **Decoded-payload escalation** (`ho-obf-003`): when base64 decodes to imperative English and the
   payload signal is above threshold, raise to `block` even without an injection keyword — currently a
   `flag`, which is the wrong default for an envelope.
3. **Non-consensual intimate imagery** (`ho-nsfw-002` category gap): a `ncii` policy on
   `photo|image + of + (my|their|ex-) + (sister|girlfriend|teacher|classmate|minor)`.
4. **Insult lexicon breadth** (`ho-toxic-001/-004`): dignity attacks without slurs; the safe move is
   `flag` + softener, not block, to protect the 0.00% false-block rate.
5. **Financial-channel vocabulary** (`ho-illegal-002`): `hawala|hundi|layering|smurfing` into
   `financial_crime_solicitation`, plus `require_all_clauses` with an evasion clause to avoid
   flagging news copy about hawala.
6. **Second annotator** for the borderline band, and a second held-out set authored by someone else —
   until then the 72.7% carries one person's blind spots, and it should be quoted that way.

Each of these is a `policies.yaml`/`injection.py` change *plus* a new held-out row, *then* a
re-measurement — never the other way round.
